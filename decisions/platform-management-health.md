# Observe service health in the current reconciliation run

Run a collector on every enrolled cluster. Place the metric, log and alert receivers on the shared operations cluster. Derive their cross-zone traffic from service functions, placement and the published listener ports. A different implementation of the same function can serve the same role. Preserve the provider, version, licence and source digest as product facts.

A step names its service, run and completion token. All three must match one healthy observation before the step completes. A matching unhealthy reading produces a finding with its observation as witness. A service with no matching observation remains unknown. In the synthetic example two step identities differ by service and an isolated cluster has no observations. Moving the mismatched service observation to the required service supplies the missing proof.

The real fixture uses the ordinary controller to apply, observe and replay on the disposable cluster. Its recorder Job runs as part of that workflow attempt and writes one JSON observation per line, with run, attempt, feature, event time and evidence reference. Each feature uses the same Job and Pod identity check. An unreachable collector must appear as unknown. Healthy and unhealthy readings use real health responses. Capture metric, log and alert deliveries independently. Opening a file of authored example events supplies no live proof.
