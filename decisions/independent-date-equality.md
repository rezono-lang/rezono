# Equality of independently recorded calendar dates

A rule can ask whether an observation belongs to the day recorded by its reference. Each record supplies its own schema `date` slot, and a separate reference slot identifies the pair of records. A match needs all three rows. An observation on the previous or following day fails the equality even if another reference carries that observation's day. A missing slot leaves the conclusion without a witness.

Use the existing equality condition between two variables bound to native date slots. The rule IR column type is `date`, and both SQL engines use `DATE`. The two identifiers and both dates are present in the witness substitution. JSON carries a date in the existing canonical YYYY-MM-DD spelling at the transport boundary. A date denotes a calendar day. A source describing UTC days supplies its UTC calendar date directly. The rule introduces no clock, timestamp conversion, date literal, epoch or freshness interval. A text or integer operand cannot stand in for one of the dates.

A single source row cannot establish that another source agrees. A text comparison would admit values outside the date domain. An integer reading on a named axis remains appropriate for elapsed days in a theory view. Requiring a common date axis or adding a second projection to that view is unnecessary for equality between two recorded dates.

The test in `compiler/tests/test_recorded_dates.py` supplies independently admitted facts. Its calendar oracle and hand-enumerated witnesses exercise a leap day, adjacent dates, missing values, unrelated records and the separate loss and restoration of each supporting row. Confirm the calendar oracle on the admitted fixture before implementing date equality. When enabling the test, add its exact node to the selectors in `compiler/ci/run_feldera_oracle.sh` and provide the successful hosted dispatch, complete collection and JUnit results for the implementation commit before queue admission. A local batch result does not establish incremental behavior.
