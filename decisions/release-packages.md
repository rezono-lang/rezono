# One distribution per registry

The version of both released archives comes from `rezono/package.json`. The editable Python projects retain their internal build metadata for source checkouts. The release wheel carries the compiler, admission, canonicalization, checker, publication and publisher Python modules, contract schemas, reproducibility locks, licences and notices. Its private directory preserves the relative layout used to fingerprint runtime sources. A path file exposes the component modules and their dependency metadata. Public entry points are `rezono`, `rezono-checker` and `rezono-publish`. The npm archive contains JavaScript compiled from the language sources, the shared canonicalizer, messages, README and licences. It references its exact external runtime dependency. The packages exclude development tests, example data, deployment files, the viewer application, toolchains and third-party code. Separate component distributions would require coordinated installations and public names. Vendoring dependencies would duplicate licence and security maintenance.

Release rehearsal installs both archives outside the checkout, publishes the valid library example to a temporary store, checks its independent proof result, and scans repository and archive contents. Only byte-identical source files with existing disclosure counts can inherit those counts. GPL indicators in any archive member stop the release. Both registries receive the artifacts produced by that rehearsal. Job summaries report sizes, scan counts and change notes grouped by commit topic.

## One-time owner setup

1. In GitHub repository `rezono-lang/rezono`, create environment `release`. Select your own account as required reviewer, leave **Prevent self-review** off, and restrict deployment branches to `main`.
2. In PyPI, select GitHub Actions as the trusted publisher for project `rezono` (use a pending publisher on the account Publishing page for a new project). Enter owner `rezono-lang`, repository `rezono`, workflow filename `release.yml` and environment `release`. [PyPI project setup](https://docs.pypi.org/trusted-publishers/creating-a-project-through-oidc/).
3. In the npm package `rezono` settings, add a GitHub Actions trusted publisher. Enter organization/user `rezono-lang`, repository `rezono`, workflow filename `release.yml`, environment `release`, and allow direct `npm publish`. Package maintainer access is required first. If the package settings are unavailable, resolve package ownership or first-registration with npm before dispatch. Perform the first authorized publication within the registry's two-day validation window. [npm trusted publishing](https://docs.npmjs.com/trusted-publishers/).
4. For an intended release, verify an unused release version and green rehearsal, select **Actions → Publish Rezono → Run workflow** on `main`, and approve the `release` deployment when requested. GitHub provides short-lived registry identities. PyPI and npm do not offer a shared atomic transaction. If npm fails after the wheel lands, rerun the failed job for the same run and artifacts. Create a `v<version>` Git tag on the released commit for the next changelog range.
