# Shared disposable cluster checks

The separate workflow is .github/workflows/disposable-cluster.yml. One runner owns one kind cluster named rezono-fixture and a private kubeconfig in its temporary directory. It creates the cluster from loop/cluster/kind.yaml, installs pinned Cilium with Hubble enabled, waits for readiness, runs the repository cluster selector, then deletes that named cluster even on failure. Use lightweight local storage. Use dedicated steps for setup, selection and cleanup. A live test can observe only the fixed synthetic resources belonging to its fixture. The ordinary required workflow stays independent.

Register the cluster marker once through a pytest entry-point plugin packaged in loop/. Repository package discovery installs it alongside the existing plugins. Normal pytest collection excludes cluster items. An explicit --rezono-cluster option enables them; the dedicated selector combines it with --strict-markers and -m cluster. Apply the marker through pytest itself so module-level, inherited and parameter marks work. Unknown marks fail strict collection. The selector discovers test components throughout the checkout, using separate collection processes where needed to preserve local conftests and imports. An individual component may have no cluster tests. No selected tests anywhere, or any collection failure, is an error. Provide a collection-only mode for offline verification.

Admission's signed desired release is a separate prerequisite. Once its renderer, policies and bindings are ready, reconcile them with Argo CD from the exact checkout and expose the shared kubeconfig and the synthetic Application identity expected by the admission test. An observed API dry-run is evidence only after that Application reports the tested revision and tracks the resources. Installing admission fixtures is independent of defining who owns the cluster. An absent provider or incomplete release must keep its integration task pending.

Serve the checkout from a runner-local Git mirror reachable inside the fixture as http://fixture-git.fixture-system.svc/rezono.git. The synthetic Application is rezono-admission in argocd. Its source is the existing k8s-admission directory at the exact tested commit. A fixture-only Argo config management plugin named rezono-admission-fixture invokes the admission release renderer against that checkout. This avoids altering the Git commit to insert generated manifests. Bind both REZONO_CLUSTER_KUBECONFIG and REZONO_ADMISSION_TEST_KUBECONFIG to the same temporary kind kubeconfig. Set REZONO_ADMISSION_TEST_APPLICATION and REZONO_ADMISSION_TEST_APPLICATION_NAMESPACE to the synthetic identity above.
