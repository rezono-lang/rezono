# Transport identity in managed namespace publications

The platform baseline has a same-zone DNS flow from idp to dns in zone platform on UDP/53. Join the function on each flow in examples/platform/oracle-rows.json to the explicit protocol in firewall-inputs.json and compare endpoint zones. Fourteen other same-zone rows are TCP. Eight UDP and thirteen TCP rows cross zones and belong to the firewall. SCTP is a supported renderer input with synthetic coverage only.

A v1alpha1 flows entry still denotes exactly one same-zone TCP tuple as specified in k8s-admission-publication.md. Keep its three required fields and list-map keys. Introduce optional spec.transportFlows for explicit UDP and SCTP witnesses, with required source, destination, protocol and port as its list-map keys. Keep the same bounds and endpoint types as flows. An absent collection is empty. Separate lists let an older policy continue checking TCP without interpreting a UDP witness as TCP. Adding protocol to the existing map would change its Kubernetes list identity and allow an older CEL expression to count a non-TCP witness as TCP. A new CRD kind would require parallel bindings.

Reconcile changes in this order:

1. Extend the structural CRD and strict offline reader together. Use strict field validation on Kubernetes submissions. Reject unknown protocols, incomplete rows, duplicate identities and invalid ports. Preserve legacy offline fixtures. Carry transportFlows as a separate collection through the reader. Keep the existing TCP-only projection for already verified TCP rows.
2. Update the managed preflight and both directions of the release-bound CEL policy. Normalize an omitted request protocol to TCP. Match the full directional identity for each requested port, including every member of an inclusive range. An old release may deny the additional transports. The legacy application-label ingress fixture remains TCP-only and may read only flows. No consumer may reinterpret transportFlows as flows.
3. Verify the same real renderer output in the independent CEL and offline binding oracles before activating a release. Stage its policy and parameters under the matching digest. Only then enable the producer to emit non-TCP rows from verified same-zone protocol evidence, sorted by source, destination, protocol and numeric port and deduplicated by that same identity. Never infer a protocol from the port number or import crossing flows. The release must remain unpublished if required transport evidence is unavailable.
