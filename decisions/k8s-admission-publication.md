# Namespace publication interchange

A verified publication supplies a release digest and namespace-qualified rows. Build and signature witnesses use (namespace, service, image) as their joint key. A flow witness uses (namespace, source, destination, port) and represents an already derived same-zone TCP flow. The producer groups verified rows by namespace before emitting parameters. An explicitly managed namespace can have empty lists. Sort images by service and full image reference, and flows by source, destination and numeric port. Remove duplicate entries after the evidence join. Witness multiplicity remains available to preflight proof accounting.

The namespaced parameter kind is AdmissionPublication in admission.rezono.org/v1alpha1. Its spec contains digest, images and flows. The adapter for the preflight evaluator reads the namespace from metadata.namespace and the three values from spec. Reading the same resource in another request namespace is an error. This explicit envelope allows the preflight and cluster paths to share cases without teaching the rule evaluator about Kubernetes metadata.

Each oracle consumes the same checked-in requests, parameter resources and expected outcomes. Create one case set per rule with synthetic namespace names. The offline harness loads the resource through the real policy binding. The disposable cluster installs the same resources and submits the same objects with server-side dry-run. An absent namespace publication is represented by omitting that resource from the case setup. Each oracle compares against the hand-written outcome independently. A connection failure or API schema rejection cannot satisfy an expected policy denial. Check the rule and release identity in the policy denial. Independently generated fixtures for each backend were considered, but could accidentally assign different evidence to the same request.
