# Dry-run evidence for a reconciled admission release

The shared disposable cluster workflow provisions its own explicit kubeconfig. Its setup reconciles a rendered admission release from the checkout. Supply a path to that ephemeral kubeconfig as REZONO_ADMISSION_TEST_KUBECONFIG. The acceptance probes use kubectl with that path for every operation. They only observe resources and submit server-side dry runs. A local default context cannot substitute for this fixture.

Use the same desired release to install the parameter CRD, its namespaced publication and the generated policy and binding pair for each rule. Fail on missing or ambiguous resources. The fixture has two managed namespaces, admission-blue and admission-green. Give both the label rezono.dev/admission=enabled. Only blue receives the checked-in sample publication. The release writer uses the existing policy and binding renderers. Give the controller the rendered objects in Git, preserving the publication digest. A handwritten replica of a rendered policy cannot witness this coupling.

After the API server has observed both policy generations, require empty expressionWarnings and match their live spec and binding references to the desired release. Dry-run the committed Pod and NetworkPolicy requests. Independently vary the Pod image, ingress port, or request namespace; only the declared image and port in blue may pass. A denial must identify the matching policy or binding and release digest, including a missing-parameter denial in green. Validate the server response for successful probes and the Kubernetes admission diagnostic for denied probes. A missing executable, authentication failure or schema rejection is an infrastructure failure.

The workflow and cluster bootstrap belong to the reconciliation component. The admission component owns its release renderer, fixture manifests and probes. The live check waits for the shared cluster driver, the CRD, both complete hand-written policies, both bindings and release reconciliation. The desired-state composition can be tested before a cluster is available.
