# Run the live Feldera oracle after merge

Run a dedicated GitHub Actions workflow, .github/workflows/feldera-oracle.yml, every night on main (cron `17 2 * * *`, UTC) and by manual dispatch. It does not run on a push to main. Keep the existing required pull-request check within its time budget. Use an ephemeral service on the standard GitHub-hosted Linux runner. Give the job read-only repository access. It requires no repository secrets, paid service, persistent deployment or external credentials.

The CI builder owns .github/workflows/feldera-oracle.yml and its entry point, bash compiler/ci/run_feldera_oracle.sh. The workflow runs on ubuntu in four jobs, each with its own timeout: `seed` compiles the stock Feldera dependencies once (20 minutes), `compare` runs nine shards in parallel (120 minutes each), `oracle` merges the shard reports and verifies them (10 minutes), and `report` records a confirmed disagreement of a scheduled run on main as an issue (15 minutes). One run at a time per ref, without cancelling a running one.

Why nightly and not on every push to main: one run compiles thousands of generated operator crates and can take up to an hour, so a run per merge would queue behind the next merge and report on a revision that is already gone. A nightly run on main compares the whole tree once a day, and its report names the first disagreement and the last green revision of main. A change to Feldera SQL generation or to the live comparison does not wait for the night: its author dispatches the workflow on the pull request's branch, and the required evidence review (scripts/feldera_admission.py) accepts the pull request only with a successful dispatch for its exact head revision.

Start the Feldera image pinned by digest in compiler/ci/run_feldera_oracle.sh. Verify that this image supports the HTTP pipeline API and Rust UDF compilation used by compiler/tests/feldera.py. Bind the service to loopback, bound the readiness wait and the job time, and remove the service and its local data on every exit. Use the repository's locked Python dependencies, generated contract types and the existing Souffle bootstrap for example collection.

Run the existing live compiler tests for calculations, bounds and rule properties; the example SQL and incremental-rule suites; and the platform delta/proof test. Use exactly the same node selection and repository root for collection and execution. Record the collected node IDs, one per line, before running them. Reject an empty compiler or example selection, an absent platform delta test, a missing endpoint and collection errors. Set FELDERA_URL before collection. Pass the recording and the resulting pytest JUnit XML to the verifier below. Retain the test report on failure. Do not retry broken comparisons as successful empty runs.

The compiler owns compiler/ci/verify_feldera_run.py. Its positional arguments are the collected-node file and the XML report. Require the exact collected cases to appear once and pass, including parameter cases. The platform live test and at least one live compiler case must be present. Pytest can exit successfully when all selected cases skipped. Any skipped, failed, errored, missing, duplicated or unexpected case must produce a nonzero exit. Missing or malformed inputs also fail. The worker implementing this verifier can use the standard library alone.

The separate workflow task depends on the verifier and the platform delta test being on main. GitHub enables dispatch from the default branch. Merge the reviewed workflow, then verify its first scheduled run or a manual dispatch on main. The first successful run must include actual passing compiler and example comparisons and the platform proof comparison in its report. A workflow definition or a skipped run cannot establish engine parity.

## Automatic dispatch and resume for pull requests

Manually running `gh workflow run feldera-oracle.yml --ref <branch>` for every pull request that touches the Feldera backend or live comparison stalls automated merges even when all fast checks are green. A dedicated trusted workflow, `.github/workflows/dispatch-feldera-evidence.yml`, and its stdlib-only executor, `loop/feldera_dispatch.py`, automate both dispatch and completion recovery without repository secrets, PATs or widening permissions on `.github/workflows/feldera-oracle.yml` or `.github/workflows/red-policy.yml`:

- **Trusted execution boundary:** `.github/workflows/dispatch-feldera-evidence.yml` checks out `ref: ${{ github.sha }}` from the default branch (`persist-credentials: false`, pinned by full commit SHA) and runs `python3 -I loop/feldera_dispatch.py` with `GH_TOKEN: ${{ github.token }}`. Its top-level permissions are strictly `contents: read`, `pull-requests: read`, and `actions: write`. `.github/workflows/feldera-oracle.yml` stays strictly `contents: read` (because it executes untrusted pull request branch code), and `.github/workflows/red-policy.yml` stays strictly read-only (`actions: read`, `contents: read`, `pull-requests: read`).
- **Handling GitHub Actions `GITHUB_TOKEN` non-recursion:** `GITHUB_TOKEN` with `actions: write` can create a `workflow_dispatch` run on `.github/workflows/feldera-oracle.yml`, but a `workflow_dispatch` run created with `GITHUB_TOKEN` may not emit a downstream `on: workflow_run` event to `.github/workflows/resume-feldera-review.yml`. Therefore `.github/workflows/dispatch-feldera-evidence.yml` combines two triggers:
  1. `workflow_run` on `workflows: [Review test evidence]` (`types: [completed]`), gated on `event == 'pull_request_target'`, `path == '.github/workflows/red-policy.yml'`, and `conclusion == 'failure'`, for immediate dispatch when the Feldera evidence gate blocks a pull request.
  2. `schedule` (every 10–15 minutes, e.g. `4,19,34,49 * * * *`, with `timeout-minutes` at most the schedule interval) and `workflow_dispatch` for trusted reconciliation on `main`: scanning open non-draft same-repo pull requests targeting `main`, re-running `Inspect test evidence` once a passing proof exists (`scripts/feldera_admission.py`'s `proof(head, branch, repo)` with `run["updated_at"] >= job["started_at"]`), and dispatching any blocked pull request that still has no `feldera-oracle.yml` run for its current head SHA.
- **Safety, deduplication and anti-loop invariants:**
  - **Fork-proof:** strictly requires `head_repository.full_name == GITHUB_REPOSITORY` on the triggering event and live pull request (`head.repo` non-null and matching `GITHUB_REPOSITORY`).
  - **Draft-proof:** skips draft pull requests (`draft: true`); `ready_for_review` re-runs `Review test evidence` when the pull request is ready.
  - **Gate-specific:** acts only when the latest `Review test evidence` run for `(pr, head, branch)` completed with `failure` and its latest `Inspect test evidence` job failed specifically at step `Require live Feldera evidence for backend changes` (never when `scripts/red_guard.py` or another step failed).
  - **Current-head-only:** acts only on open pull requests targeting `main` whose live `head.sha` equals the reviewed `head`.
  - **At-most-once auto-dispatch per `(head, branch)`:** never dispatches if any `workflow_dispatch` run of `.github/workflows/feldera-oracle.yml` for `(head_sha=head, head_branch=branch)` in the same repository already exists (whether `queued`, `in_progress`, `requested`, `waiting`, `pending`, `success`, `failure`, `timed_out`, `action_required` or `cancelled`). Active runs on an older SHA of the same branch do not block dispatching the current SHA.
  - **Delegated proof verification and anti-loop rerun guard:** `loop/feldera_dispatch.py` delegates proof verification to `scripts/feldera_admission.py`'s `proof(head, branch, owner)` (never trusting `conclusion == 'success'` without artifact and JUnit verification) and only posts `actions/jobs/{job_id}/rerun` when `run["updated_at"] >= job["started_at"]`.
  - **Safe dispatch payload and concurrency:** posts `actions/workflows/feldera-oracle.yml/dispatches` with JSON `{"ref": branch}` on stdin (`--input -`), under `concurrency: { group: feldera-dispatch-${{ github.event.workflow_run.head_sha || 'sweep' }}, cancel-in-progress: false }`.
