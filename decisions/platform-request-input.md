# Loading platform requests for a proposal preview

The public example entry point is `examples/platform/request_preview.py`. It takes `--pack`, `--teams` and `--catalog` paths. The `inputs` command emits normalized compiler input tables as a JSON object. The `relation NAME` command evaluates the same inputs through the pack and emits sorted JSON rows of the requested derived relation. Both commands read the files supplied on each invocation. The portal, CI and local users can run this same read-only preview.

Take team and service identity from the two directories above each request.json. Preserve the submitted profile, items, sizes and connection declarations as typed records. For an item the stable row identifier is team/service/item. Catalog offers use item/size. The `tenant_request_item` kind has tenant, service, item and size attributes. The `tenant_catalog_offer` kind has an integer monthly_cents attribute. A service request and its connections also retain distinct identities. Reject unknown or malformed fields and invalid references before evaluation. Catalog prices and totals are integer EUR cents.

Read the existing platform pack and declared schemas with the compiler. Convert the validated records to base tables using `rezono_compiler.facts.rows_of`. Combine them with ordinary platform fact tables by appending rows of the same table. Run the normal rule or calculation program with this combined state. The public command handles input and output. A pack rule or exact calculation owns the price join and aggregation. The reference program has its own file reader and arithmetic and is only an expectation source.

The input task owns the public command and tenant request input schema. It can be accepted before any cost relation exists. The cost task owns a separate calculation or rule module. Its acceptance uses the public command, exercises a request change and a catalog price change, and requires the other tenant's total to stay unchanged.
