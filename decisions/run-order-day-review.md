# Recheck the payable amount before an offline order request

Plan the intended order day against the captures available at quotation. Revalue that day against a fresh pair of recorded price and FX sources when preparing an order. Require the same plan digest, selected source digests, provider and complete payable total. The charge includes every machine's setup and all billed periods. A lower amount under the budget still requires a renewed approval when the plan digest changes. The proposed plan bytes are the bytes hashed for the existing approval and rendering boundaries.

Use the effective quote and dispatch rule defined in the run decisions. The new offline entry points are `run/order_day_review.py:plan(day, lines, prices, rates, provider)` returning immutable JSON bytes and `review(approval, instant, day, lines, prices, rates, guarantee)` returning a candidate hash, reason and optional request. A guarantee identifies the provider, the currency, the bound on the whole order and its exclusive expiry. A binding quote fixes the amount. A reject-above order instructs the provider to reject charges greater than the exact approved total. Both must cover setup. The returned inert request carries the plan hash, currency, total monetary bound, mode and exclusive expiry. Limit expiry by the earliest of approval expiry, the provider guarantee and the next UTC midnight; equality is expired. Never call a provider to run this check.
