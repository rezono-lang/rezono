# Require an origin for every fact row: a warning in rezono 0, a refusal from rezono 1

The [project vision](../docs/vision.md#facts-and-conclusions) says: "A fact has an origin: a decision, a vendor publication, a design choice or an observation. A row without an origin is not a fact." Nothing holds a pack to it. The compiler gives every row that cites nothing an implicit source, its own fact file and line (`{kind: pack, name: facts/<file>, position: <line>}`, the fallback in `text_entries` of [`compiler/rezono_compiler/sources.py`](../compiler/rezono_compiler/sources.py)), and the [source contract](../contracts/source.yaml) accepts `pack` as a kind. Only a malformed sidecar is refused, and the publisher blocks only on an invalid source set. That locator says where a row is written, not why it holds. The owner adopted the advice to enforce the rule: warn first, refuse from `rezono 1` on. This decision says what counts as an origin, adds the warning W113, the refusal R053 and the publisher's check row `rezono:origins`, and adds the source kind `synthetic` for generated example data. [Fact provenance](language-fact-provenance.md) · [std-decision](../packs/std-decision/README.md) · [Fact classes](../docs/compiler/import.md#fact-classes)

## 1. What an origin is

A base row has an origin when one of the following holds. The compiler judges it per row, from the row's source entry (what `generated/sources.json` holds) and the pack's facts.

| Origin | How a pack writes it | Why it is one |
| --- | --- | --- |
| A citation | `fact Kind @ name` with a `source` declaration ([fact provenance](language-fact-provenance.md)), or `@ source#locator` after a value ([v0 §5g](../docs/rezono/v0.md#5g-sources-and-interpretations)) | it gives the row a source of another kind than `pack` |
| A sidecar entry | a `default`, `records` or `rows` entry in `facts/<file>.sources.yaml` | the same |
| A `decide` block | `decide "<title>" by <decider> on <date>` and the values it sets ([v0 §5](../docs/rezono/v0.md#facts-decisions-and-assumptions)) | the block names who decided and on which day; an `@` on the block is also the source of its values |
| A decision the row is bound to | a record whose kind has an arrow to std-decision's `Decision`, or to a subkind of it, with a value | the decision is the origin of every row of that record |
| A decision record | a `Decision` record that names its `decider` and its `decided_on` | a decision is its own origin |

For the first two, every kind of the contract except `pack` and `scenario` (section 2) gives an origin, with one exception: a `git` source whose position, before `#`, is the row's own fact file (as `facts/<file>` from the pack root, or the same file from the repository root) is the row citing itself.

The vision's four origins map onto these forms. No source kind named after them is added.

| The vision says | A pack writes |
| --- | --- |
| a decision | a `decide` block, a `Decision` the record is bound to, a `Decision` record, a `proposal` source (the proposal and delta step that brought the row in), or a `git` source that names the decision's file at a pinned revision |
| a vendor publication | a `document` source (URL, fragment hash, licence and attribution) or a `git` source at the vendor's pinned commit |
| a design choice | a decision, written as above; in this repository usually a `git` source that names `decisions/<id>.md` at a pinned revision |
| an observation | a `query`, `tool` or `person` source; an observation the loop admits enters with its observer's source of one of these kinds and needs nothing more |

## 2. What is not an origin

- The implicit source the compiler gives a row that cites nothing: `{kind: pack, name: facts/<file>, position: <line>}` for a fact file, and the module's file and place for a fact table in a module. It stays the row's locator in `generated/sources.json`; it is no longer read as an origin.
- A source of kind `pack` written out in a sidecar or a `source` declaration. It says the same.
- A `git` source that names the row's own fact file (section 1).
- A comment in the fact file, such as "generated by generate.py". The compiler does not read comments.
- A `scenario` source. A scenario overlay is a supposition of a variant, not one of main's facts, and the check reads main's facts only.

An `assume` line is not a fact. It marks its value as an assumption, which every proof that rests on it shows ([v0 §5](../docs/rezono/v0.md#facts-decisions-and-assumptions)). It needs no origin and gets neither W113 nor R053.

## 3. Generated example data: the source kind `synthetic`

Example data that a script or an author makes up to exercise rules has none of the four origins, and it must say so. `SourceKind` in `contracts/source.yaml` gets one member:

```yaml
synthetic: {description: "Example data made up to exercise rules, not taken from the world: name is its generator, position the seed and the part of its output."}
```

- `name` is the generator: the script that writes the file, as a path from the repository root (`examples/subsidy/generate.py`), or, for example data written by hand, the document that describes the example (its README or the decision that sets it up).
- `position` is the seed and the part of the output (`seed 20261110#household`), or the section of that document.
- No other field is required. `revision` is optional: the pack's own commit pins a generator in this repository.
- A script that writes a fact file writes its sidecar in the same run, so the source changes with the output it describes (root [AGENTS.md](../AGENTS.md), rule 2).
- A `synthetic` source is an origin for W113 and R053: the row says what it is. Whether synthetic data is published stays the deploy profile's choice, through the pack's class (`publish.classes`, SO-5).
- The compiler reads the kinds from the contract (`sources.kinds()`), so it accepts the new kind with the contract. The checker restates them (`KINDS` in [`checker/rezono_checker/sources.py`](../checker/rezono_checker/sources.py)), and a test holds that list to the contract. That file is read before it lands ([checker and access review](checker-and-access-review.md)).

Not `tool`: a tool reports a status or a measurement of something that exists. Not `pack`: that names a place, not a reason.

## 4. Phasing and codes

| Language of the pack | A row without origin | Effect |
| --- | --- | --- |
| `rezono 0` | W113, a warning | the compile goes on; every row keeps its locator |
| `rezono 1` and later | R053, a refusal | nothing is compiled |

The language of a pack is the one its `rezono` modules declare; a pack without modules is on `rezono 0` ([v0 §4b](../docs/rezono/v0.md#4b-language-version-and-deprecation), [Rezono 1, section 5.8](language-rezono-1.md#8-module-format-version-is-rezonomodule5)).

- **One diagnostic per record and place.** The rows of one record (its kind and identifier) that one place gives, and that have no origin, make one W113 or R053. The place is the record's line in the fact file, or the row's line in the module, as the implicit source names it. Rows the same record gets with an origin from another place, such as a value a `decide` block sets, are not reported. Every such record is reported, not only the first.
- **On the command line** it is one line: the severity, the code, the place as `<file>:<line>`, then the sentence. For example, `warning: W113 facts/a.yaml:2:` and then the sentence for `alpha` `a1`, or `error: R053 facts/a.yaml:2:` and then its sentence. The diagnostic itself has the code, the severity, the kind and identifier as `where`, and the span of the place ([diagnostic contract](../contracts/diagnostic.yaml)).
- **The sentences** go into `rezono/messages/en.json` and `rezono/messages/nl.json`, with `{0}` the kind and `{1}` the identifier, and both codes into the table of [v0 §10](../docs/rezono/v0.md#10-diagnostics) when they are built.

| Code | en | nl |
| --- | --- | --- |
| W113 | `{0}` `{1}` has no origin: only its file and line name it; give it an `@` citation, a `decide` block, a `Decision` it is bound to, or an entry in its `.sources.yaml` (kind `synthetic` for generated example data) | `{0}` `{1}` heeft geen herkomst: alleen het bestand en de regel noemen het; geef het een `@`-bron, een `decide`-blok, een `Decision` waaraan het gebonden is, of een regel in zijn `.sources.yaml` (soort `synthetic` voor gegenereerde voorbeelddata) |
| R053 | `{0}` `{1}` has no origin, and a `rezono 1` pack refuses a fact without one; give it an `@` citation, a `decide` block, a `Decision` it is bound to, or an entry in its `.sources.yaml` (kind `synthetic` for generated example data) | `{0}` `{1}` heeft geen herkomst, en een pack op `rezono 1` weigert een feit zonder herkomst; geef het een `@`-bron, een `decide`-blok, een `Decision` waaraan het gebonden is, of een regel in zijn `.sources.yaml` (soort `synthetic` voor gegenereerde voorbeelddata) |

- **The codes.** W113 is the first W code after W112, the last one in v0 §10 and in the message files. R053 is the first R code that no register, decision or open pull request used on 2026-11-20: v0 §10 lists R001 to R034, the message files R035 to R037, [native rules](language-native-rules.md) R040 to R049 and [calculations](language-calculations.md) R050. R038 and R039 are a gap without a recorded reason and stay free. R051 was claimed the same day by the draft on Rezono 1 defaults, and R052 was held for the draft on aggregate spelling while this was written; that draft took no code, so R052 stays free.

## 5. The publisher's check row `rezono:origins`

- The manifest of every epoch has one `CheckResult` named `rezono:origins`. Its `violations` is the number of main's base rows, by RowRef, that have no origin by sections 1 and 2.
- Its `status` is `green` when that number is 0, `warning` when it is more on a `rezono 0` pack, and `red` when it is more on a `rezono 1` pack. A red row blocks the publication like any red check. The compiler refuses such a pack first; the row still holds for an epoch made from source entries that did not pass the compiler.
- **One judgment, in the compiler.** A function beside the source reader in `compiler/rezono_compiler/sources.py` gives the rows without origin, grouped by record and place. The compile command turns them into W113 or R053. The batch (`edge/publisher/rezono_publisher/batch.py`), which already gives the epoch its `fact_sources` from the same reader, adds the check row to the epoch's `checks`. `publish.py` writes the epoch's checks into the manifest and blocks a red one, as it does today. So neither `publish.py` nor the publisher's `sources.py` needs to change; a pull request that changes them anyway is read before it lands.
- The count is over all of main's rows, like the violation count of an integrity check, and it names no row. The per-role source sets and their check `rezono:sources` do not change.
- The checker does not derive the count again. An origin is a property of what the pack's author wrote, not of a proof, and a source stays a locator: not proof of where a row really came from.

## Alternatives

- **Keep `pack` as an origin and only report it.** The rule would stay a sentence that nothing holds.
- **Refuse at once, in `rezono 0` too.** Half of the platform and every other example would stop compiling on the day it lands. `rezono 0` is the workbench; the owner chose to warn first.
- **A source kind for each of the vision's origins (`decision`, `vendor`, `design`, `observation`).** The existing kinds already say what was observed or published. A decision is better a `Decision` row or a `decide` block, which give the decider and the day typed slots; a `decision` kind in a sidecar would hold them as text.
- **Count the rows without origin in the checker.** An origin is not a property of a proof, and the checker stays independent of how a pack was authored.
- **One W113 per row.** A generated population would give thousands of lines. One per record and place points at the line to change.
- **Read a generator's comment as its origin.** Comments are not read, and a generator that writes its sidecar keeps the two in step.
