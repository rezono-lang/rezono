# Rezono v0 language reference

This reference describes the Rezono v0 language design. See [Expressions and questions](expressions.md) for the detailed expression grammar and [the implementation guide](../../rezono/README.md) for current support. Reserved constructs and design examples describe intended language behavior.

## 1. Goals and limits

1. **Readable by a domain expert.** A rule reads like the thought behind it.
2. **Exact.** Units, value states, worlds, rights and provenance are part of the type, so mistakes are compile errors, not wrong answers.
3. **Total.** Every program terminates. No functions, no loops, no recursion beyond stratified Datalog, no side effects. (Termination; a *total definition*, §5d, promises a known value.)
4. **One core.** Every construct desugars deterministically to the existing IR and contracts. The language adds no meaning of its own, so the oracles keep holding.
5. **No user-defined syntax.** No macros and no operator overloading. One obvious way to write each thing.
6. **Evolves without breaking.** A valid text keeps its meaning under the language version it declares (§4b), and a published surface changes only additively (§4c).

## 2. Settled choices

| Question | Choice for v0 | Reason |
|---|---|---|
| Aggregates | **method form only**: `clusters.sum(count * spec.nodes)`; no comprehension | reads like the thought; one form keeps the language small |
| Ranges | `a..b` is inclusive, `a..<b` is half-open, for every ordered type | one rule everywhere; validity periods use `..<` |
| Block structure | indentation (two spaces), no braces, no tabs | matches the examples and YAML; the printer enforces it |
| Element ids | bare when they match `[a-z][a-z0-9-]*`; otherwise in backticks: `` `stage-a/plan-a` `` | `host-b` stays readable; `-` as an operator needs spaces around it |
| `unless` | ordered precedence inside one derived value; later blocks win. Lines inside one `unless` block are **siblings**: two that apply together are a violation with both witnesses, never a silent pick (§5b) | Catala default logic: precedence where the text orders, conflict where it does not |
| Rights as types | labels are inferred and checked; in v0 a read above a role's clearance is a **warning**, in v1 an error | the gate already refuses at run time; the compile-time check is new and needs a season to settle |
| Fact tables | allowed for hand-authored facts; bulk data stays canonical (Parquet, Arrow) | readable diffs for people; no text formats for millions of rows |
| Literals | the core knows only generic literals; specific ones (units, currencies, IP addresses, IBANs) are **literal types declared by packs**, read by the type the context expects | new domains need no grammar change |
| Soufflé syntax | output only, for the oracle | people never write it |
| Schema | `kind` in Rezono; LinkML as import and export | worlds, inverses, units and states become language, not annotations |
| Truth | four states in every operator, by fixed tables (§7b); at a decision point `n/a` means "does not apply" | OCL 2.4; replaces "n/a counts as false" |
| Validity | definitions and facts have **versions** with a context (`valid`, `during`, `in`) and a `known` date; exactly one applies per subject (§5a) | one model for dates, stages and setups |
| Applicable context | per subject (`applies at \| during \| in`), else the question's, else the manifest's (§5a) | a decision is judged by the rules of its date |
| `check`, `norm` | `check`, `require` block publication; `norm` records a violation without blocking (§5; reserved) | SBVR, FLINT |
| Decision tables | `table` with hit policy `unique`, `first`, `priority`, `collect`; gaps and overlaps proven (§5c) | DMN |
| Effects | `computes`, `reads`; commands also `transacts`, `writes` (§5d) | Verse |
| Totality | `total` (proven known) or `partial` (default) (§5d) | Verse: may fail versus must succeed |
| Language version | `rezono 0` per file; deprecations warn first, fail only in a later version (§4b) | Verse |
| Reasons | a code with a label: `reason no_rate = "…"` (§5) | the data carries a stable code |
| Dates | calendar units `month`, `year`; a declared date rounding (§5f) | Catala, FEEL |
| Sources | article locators; interpretations as versions (§5g) | ELI, Juriconnect |

## 3. Lexical structure

- **Encoding:** UTF-8. Line comments start with `--`. A doc comment `---` attaches to the next declaration and shows in the viewer.
- **Names:** kinds and units `[A-Z][A-Za-z0-9]*`; slots, rules, parameters `[a-z][a-z0-9_]*`; element ids as above.
- **Keywords:** `pack use as private unit enum param kind extend derived rule check warn require fact decide assume theory view example ask suppose propose when then else unless where show not and or in is version valid known at by on because until requires sources world open closed inverse rezono norm exception applies replaces deprecated`.
- **Contextual words** are keywords only in a particular position: `during` (in a context), `table` and `unique first priority collect` (in a derived body), `of` (after `exception <label>`), `total partial computes reads` (before a declaration; `transacts` and `writes` classify commands only, §5d), `reason rounding` (at the start of a declaration), `sealed` (in a kind), `violation` (in `expect`). Other positions can use these words as names.
- **Core literals.** The lexer knows only these; each is typed by its own form:

| Literal | Example | Type |
|---|---|---|
| exact number | `16`, `0.1610`, `3/4` | integer or exact fraction |
| percentage | `21 %` | `Ratio` |
| quantity | `64 GiB`, `90 s`, `1 month` | a number and a unit declared by a pack (§5, §5f) |
| date, datetime | `2026-11-08`, `2026-11-08T14:02:00Z` | `Date`, `DateTime` (ISO 8601; validity and knowledge time are core) |
| range | `65001..65099`, `2026-01-01..<2027-01-01` | `Range<T>` over any ordered type |
| text | `"no monthly rate published yet"` | `Text` (domain content only) |
| state | `unknown no_rate`, `unknown "reason label"`, `n/a`, `invalid bad_format` | a value state with a reason (§5) |

- **Literal tokens.** Anything else that is one token without spaces (`192.0.2.1`, `€`, `GB00TEST00000000000000`) is a *literal token*. The type checker reads it with the literal grammar of the type the context expects, for example the slot it is assigned to, the other side of a comparison, or a parameter type. Where no type is expected, write the type in front: `Cidr"192.0.2.0/31"`, `Iban"GB00 TEST 0000 0000 0000 00"`. The IBAN illustrates the lexical pattern with synthetic digits.
- **Money** uses exact amounts and one named rounding. Currencies and their symbols come from a pack: `€ 0.16` works because `std.money` declares `€` as a prefix for `Money<EUR>`.
- **Open ranges.** In a `valid` context a range may leave its end open: `2026-01-01..` is valid from that date on. In a decision table cell (§5c) either end may be open. Nowhere else.

There is no float literal: `0.1` is the exact fraction 1/10.

## 4. Modules

```rezono
rezono 0                            -- the language version (§4b)
pack demo                  -- one pack per directory; every file declares it
use std.order                        -- a theory or standard pack
use sample.network as net          -- another pack, under a prefix
```

Declarations are visible in the whole pack. `private` hides one from other packs. A name from another pack is written with its prefix: `net.Zone`. Everything not `private` is the pack's **public surface** (§4c).

---

## 4b. Language version and deprecation

- Every file starts with `rezono <n>`. All files of one pack declare the same version (R027). A file without the line is read as `rezono 0` with W106; in a pack on `rezono 1` or later it is R028.
- The version fixes the meaning and the printed form of every construct for that pack. A compiler that supports version n gives a pack on n the same meaning as any other such compiler. A pack moves only by changing its line.
- **Deprecation in phases.** A pack may stay on its version; how long compilers keep supporting an old version is open point 1 (§14).

| Phase | Versions | Effect |
|---|---|---|
| available | up to n − 1 | none |
| deprecated | n | W107 at every use, naming the replacement; meaning unchanged |
| removed | n + 1 and later | R028, only for packs that declare n + 1 or later |

- "Rights as types" (§2) follows this path: a read above clearance is W102 in `rezono 0` and an error for packs on `rezono 1`.
- **Declarations** deprecate the same way:

```rezono
deprecated "use ProviderZone" until 2027-07-01
kind Zone  world closed
```

A use from another pack gives W107 with the text. Removal before the date is R033; after it, removal is a major change (§4c).

## 4c. Public surface and compatibility

The **public surface** of a pack is every declaration visible to other packs, each with its type, cardinality, world, reader label, effect class and totality (§5d). Each module declares its surface the same way. At publication the publisher compares the surface with the last published one and classifies the change:

| Class | Changes | Result |
|---|---|---|
| patch | doc comments, messages, reason labels, source references | published |
| minor | add a kind, slot (with a declared state for old rows), rule, derived value, check, value of an open enum, or version; widen a type or refinement; let more roles read | published |
| major | remove, rename or retype a public kind, slot or rule; change a cardinality; close an open world or enum; narrow a reader label; allow a new state (`total` to `partial`); raise an effect class; change or remove a version | R033 unless a proposal with an impact assessment accepts it; the data then gets a new schema with a mapping view |

An enum is closed unless declared `enum Name world open = …`. Published datasets evolve additively.

## 5. Declarations

### Units, enums and parameters

```rezono
unit B          = integer                     -- base dimension: data
unit GiB        = 2^30 B
unit s          = integer                     -- base dimension: time
unit h          = 3600 s
unit Count      = integer                     -- dimensionless
unit Cents      = money minor EUR             -- EUR comes from use std.money

enum VexStatus  = affected | not_affected | fixed | under_investigation

param host_reserve: GiB                       -- declared and typed; the value is a fact
param idle_limit: Count = 90                  -- with a default
param retry_limit: Count per Zone             -- may vary per zone
```

A parameter may have versions (§5a).

### Literal types

A pack declares the literal types of its domain. A literal type is text with a pattern, a normalization from a fixed list, named fields and checks in Rezono. There is no code of its own, so a literal stays deterministic and checkable.

```rezono
literal IPv4: Text
  pattern "(?<a>[0-9]{1,3})\.(?<b>[0-9]{1,3})\.(?<c>[0-9]{1,3})\.(?<d>[0-9]{1,3})"
  fields a, b, c, d: Count
  check a <= 255 and b <= 255 and c <= 255 and d <= 255

literal Cidr: Text
  pattern "(?<address>[0-9.]+)/(?<prefix>[0-9]+)"
  fields address: IPv4, prefix: Count
  check prefix <= 32

literal Iban: Text
  normalize uppercase, strip spaces
  pattern "(?<country>[A-Z]{2})(?<check>[0-9]{2})(?<account>[A-Z0-9]{11,30})"
```

Named groups become fields: `c.prefix`, `i.country`. Normalizations come from a fixed list (`uppercase`, `lowercase`, `strip spaces`, `trim`), so two spellings of one value get one canonical form and one hash. A literal type compiles to a LinkML type with a pattern.

### Kinds and slots

```rezono
--- A host in the example capacity model.
kind Host  world closed
  clusters: HostCluster* inverse host         -- * many, + at least one, ? optional
  zone: Zone
  memory: GiB >= 1 GiB                        -- a refinement: a violation view
```

Cardinality: `T` exactly one (missing is `unknown`), `T?` optional (missing is `n/a`), `T*` zero or more, `T+` one or more. `world open | closed` per kind or per slot; the default is `open`. A kind may also say which context selects versions for its elements (`applies at | during | in`) and when its values are sealed (`sealed at`), §5a.

### Derived values and rules

The [native relational rules decision](../../decisions/language-native-rules.md) defines the rule grammar, its use of question expressions, and the evidence carried through compilation.

```rezono
extend Host
  derived memory_need: GiB =
      host_reserve + clusters.sum(count * spec.nodes * spec.memory_per_node)

extend Zone
  derived available_hosts: Host* = inventory.hosts

rule listed(item: Item) when item in Item
```

- `derived x: T = e` gives one value per subject, or several with `T*`. The type is required.
- A rule defines a relation. Recursion is stratified, with no arithmetic inside the recursive part.
- A derived value with a unit, a version or definitions is a calculation: exact fractions, the four value states, one named rounding.

```rezono
extend Offer
  derived hourly_cost: Cents
      version 1, valid 2026-01-01..<2027-01-01, known 2026-10-26
    every_host_fits: when complete then round(hourly_price * 1 h)

  derived discount_rate: Ratio = 10 %
    unless preferred then 20 %
    unless ineligible then 0 %                -- later clauses take precedence
```

The proof of `discount_rate` names the clause that fired and shows that the later clauses did not apply. That needs their conditions over closed relations; otherwise the value is `unknown` with a reason. The `version` line of `hourly_cost` is the short form of a definition with one version (§5a). Sibling exceptions and exceptions from another module are covered in §5b.

### Checks, norms and requirements

```rezono
check price_cap: plan.hourly_price <= plan.max_hourly_price   -- named; blocks publication
warn  plan.parts.count() <= 8                                 -- warns only
require isolated(tenant-a, management)  because policy#isolation
check isolated(r.from, r.to) requires 2 sources               -- provenance as a condition
norm  backup_fresh: backup.age <= 26 h                        -- about the world (reserved)
```

A check that names a kind in lowercase (`plan.hourly_price`) ranges over every element of that kind, as `ask` does.

- `check` and `require` concern the model and block publication; they may not read observations (R026). `warn` records warnings. A `check` that is *undecided* (§7b) publishes an undecided violation row when the state is `unknown`. It blocks on `invalid`, which means the model contradicts itself. A `require` also blocks on `unknown`, so an isolation claim cannot pass on missing data. `norm` concerns observations and records a violation row with witnesses without blocking an epoch.
- A name (`price_cap:`) is required when a check has versions, is named in `expect violation` (§5e) or is excepted; an anonymous check is reported as `<file>:<line>`.
- A check passes when its condition is true or `n/a`, is violated when false, and is *undecided* when unknown or invalid (§7b).
- The `norm` form illustrated here is **reserved** in this grammar; a compiler that does not support it reports R015.

### Facts, decisions and assumptions

```rezono
reason no_monthly_rate = "no monthly rate published yet"

fact plan plan-a
  provider     = cherry
  memory       = 64 GiB
  hourly_price = € 0.1250/h          @ example-prices#2026-11-08
  monthly_price = unknown "no monthly rate published yet"

fact Plan                                      -- a table, for hand-authored sets
  | id     | provider | memory  | hourly_price |
  | plan-a | cherry   | 64 GiB  | € 0.1250/h   |
  | plan-b | cherry   | 128 GiB | € 0.2500/h   |

decide "Assign identifiers to the example switches" by reviewer on 2026-10-21  @ policy#identifiers
  switch-a.asn = 65001
  switch-b.asn = 65002

assume plan-a.memory = 64 GiB  until confirmed
```

`@` names the source of one value; `decide` gives all its facts one source, a decider and a date; `assume` marks the source as an assumption. Every proof that rests on an assumption shows it, and `ask Assumption` lists them all.

**Reasons.** A reason is a code (`[a-z][a-z0-9_]*`) with a label, declared once per pack with `reason`. A state literal names the code (`unknown no_monthly_rate`) or a declared label (`unknown "no monthly rate published yet"`); both store and print the code. An undeclared label is R029. Core codes need no declaration: `no_version_applies`, `versions_overlap`, `exception_conflict`, `no_row_applies`, `ambiguous_date`, `empty`, `added_later`.

A `fact` or `decide` may carry a context (`fact plan plan-a, valid 2026-01-01..`); it is then a version of those values (§5a).

### Theories and views

```rezono
theory Order<T>
  rule before(a: T, b: T)
  check not before(x, x)                         -- irreflexive
  check before(a, b) and before(b, c) => before(a, c)

view Stage as std.Order<Stage>
  before(a, b) = a.position < b.position
```

The compiler checks that the view satisfies the theory's checks. A domain gets the theory's rules and sheets through the view.

### Examples

```rezono
example "round an hourly rate to cents"
  given
    plan-a.hourly_price = € 0.1250/h
  expect
    plan-a.hourly_cost = € 0.12
```

An example can document an expected result and serve as a test against the engines and oracles. See §5e for negative examples, contexts and coverage.

### Standard packs

The literal types and units that most packs share come as standard packs, not as part of the language. They can arrive or grow after v0 without a grammar change.

| Pack | Declares |
|---|---|
| `std.units` | SI and IEC units with exact factors: `B`, `KiB`, `GiB`, `s`, `min`, `h`, `d`, …; calendar units `month`, `year` (§5f) |
| `std.money` | ISO 4217 currencies, their minor units and symbols (`€`, `$`), `ExchangeRate<A, B>` |
| `std.net` | `IPv4`, `IPv6`, `Cidr`, `Port` (`tcp/179`), `Asn` |
| `std.iban` | `Iban` |

A domain pack can declare more literal types, for example an account code or a legal reference.

## 5a. Validity and applicability contexts

Every definition (`rule`, `derived`, `check`, `warn`, `require`, `norm`, `param`) and every `fact` and `decide` may have **versions**. A version has a **context** on up to three axes and a **knowledge date**:

| Axis | Form | Holds when |
|---|---|---|
| date | `valid 2026-01-01..<2027-01-01`, `valid 2026-01-01..` | the subject's date lies in the range |
| stage | `during stage-a`, `during stage-a..<stage-c`, `during stage-b..` | the subject's stage lies in the range, by the order of the stage kind (a view of `std.Order`, §5) |
| setup | `in setup-a`, `in setup-a \| setup-b` | the subject's setup is one of these: a lab setup, an environment or a variant (the same notion as sweep variants and `suppose` scenarios) |
| knowledge | `known 2026-10-26` | the version is known from this date on |

A version without a condition on an axis holds for every value of it. A stage context is one stage, a half-open range or an open range.

```rezono
param standard_premium: Money<EUR>
  version 1, valid 2025-01-01..<2026-01-01, known 2024-09-17  = € 1800.00  @ example-policy#art-1
  version 2, valid 2026-01-01.., known 2025-09-16             = € 1810.00  @ example-policy#art-1

param retry_limit: Count
  version 1, during stage-a..<stage-b  = 2
  version 2, during stage-b..         = 4
```

**Subjects.** The subject of a definition is the kind it extends (`derived`), its first binder (`rule`; another binder is open point 11), the kind it ranges over (`check`, `norm`), or the kind after `per` (`param … per Zone`). A definition without a subject (a plain `param`, a `decide`) uses the question’s context when a question reads it directly, and on the date axis the date of the calculation that reads it (rule 6).

**The applicable context, per subject.** A kind may name the slots that give its elements their context:

```rezono
kind Claim  world closed
  applies at: decision_date          -- versions are chosen at this date
  decision_date: Date
  started_on: Date
```

1. Per axis, the context of subject `s` is the slot its kind names in `applies at | during | in`; else the question’s context (see [question grammar](expressions.md#4-grammar), or an example’s context, §5e); else the manifest’s context, which defaults to the date of its knowledge time and has no stage or setup. Where the question and subject both give a date, the subject’s date wins.
2. A kind names each axis at most once, and the slot has the axis type: `Date` or `DateTime` for `at`, a kind with a `std.Order` view for `during`, any kind for `in` (R022).
3. **Knowledge.** Only versions with `known` at or before the knowledge cut count. The cut is the question's `as known`, else the manifest's knowledge time. A version without `known` is known from its first publication.
4. **Exactly one version applies.** Among the versions whose context holds, precedence decides: (a) an explicit `version m replaces n [unless c]` line; else (b) the version with the later `known` date, which corrects the earlier one on the overlap; else (c) the value is `invalid versions_overlap`, with a violation that carries both witnesses. If no version holds, the value is `unknown no_version_applies`. Where constants show it, the compiler reports an overlap (R020) or a gap (W108; R024 for a `total` definition).
5. A fact with a context is a version of those values per slot; the same rules apply. In published data it carries `$valid` and `$known`.
6. **Reads inside a calculation inherit the date.** A calculation for subject `s` has the effective date of rule 1: the slot of `s`’s `applies at`, else the question’s date, else the manifest’s. Every version it selects on the date axis is selected at that date:
   - **A parameter read:** a definition without a subject read inside the calculation, a plain `param` or a `decide`, takes the calculation’s date.
   - **A read through a relation:** a value of an object `o` reached by a path takes `o`’s own `applies at` if `o`’s kind names one. Otherwise it takes the calculation’s date. Where the value of `o` is itself a calculation, `o` is its subject and its date is the one `o`’s value was read at, so the date passes along a path.
   - **Fallback.** Only where the subject gives no date does the question's date apply, then the manifest's (rule 1); a question that reads a value directly uses its own context as before.
   - **Knowledge stays separate.** The knowledge cut of rule 3 (`as known`, else the manifest's knowledge time) applies to every read alike: a version known after the cut takes no part, whatever its date. The rule concerns the date axis only; stage and setup follow rule 1.

**Specification example.** A question asked in January about a December month illustrates the date and knowledge rules. It is a design example.

```rezono
param contribution_rate: Ratio
  version 1, valid 2025-01-01..<2026-01-01, known 2024-09-17  = 6.50 %
  version 2, valid 2026-01-01.., known 2025-09-16              = 7.00 %
  version 3, valid 2025-12-01..<2026-01-01, known 2026-01-20  = 6.80 %   -- known after the cut below

kind Person  world closed                 -- no applies at: a reached value takes the reader's date
  income: Money<EUR>

kind Policy  world closed
  applies at: set_on                      -- its own date wins when it is read
  set_on: Date
  cap: Money<EUR>

kind ClaimMonth  world closed
  applies at: first_day
  first_day: Date
  claimant: Person
  policy: Policy

extend ClaimMonth
  derived contribution: Money<EUR> = contribution_rate * claimant.income
  derived capped: Money<EUR> = policy.cap

fact person person-a, valid 2025-01-01..<2026-01-01, known 2025-03-01
  income = € 30000.00
fact person person-a, valid 2026-01-01.., known 2025-12-01
  income = € 36000.00
fact person person-a, valid 2025-12-01..<2026-01-01, known 2026-01-20
  income = € 31000.00                     -- a December correction, known after the cut

fact policy p1
  set_on = 2026-01-05
fact policy p1, valid 2025-01-01..<2026-01-01
  cap = € 1200.00
fact policy p1, valid 2026-01-01..
  cap = € 1300.00

fact claim_month dec-2025
  first_day = 2025-12-01
  claimant  = person-a
  policy    = p1

ask ClaimMonth at 2026-01-10 as known 2026-01-15 where first_day = 2025-12-01 show contribution, capped
ask Person at 2026-01-10 as known 2026-01-15 where income is known show income
```

| Read | Date used | Versions | Value |
|---|---|---|---|
| `contribution_rate` in `dec-2025.contribution` | 2025-12-01, the month’s `applies at` | version 1; version 3 is known after the cut 2026-01-15 and takes no part; version 2 is not valid in December | 6.50 % |
| `claimant.income` in `dec-2025.contribution` | 2025-12-01, inherited: `Person` names no `applies at` | the December fact; the correction is known after the cut; the January fact is not valid | € 30000.00 |
| `dec-2025.contribution` | | 6.50 % × € 30000.00 | **€ 1950.00** |
| `policy.cap` in `dec-2025.capped` | 2026-01-05, `p1`'s own `applies at`, which wins over the month's date | the 2026 fact | **€ 1300.00** |
| `person-a.income`, asked directly | 2026-01-10, the question's date (fallback: no subject date) | the January fact | € 36000.00 |

With `as known 2026-02-01` both December corrections count: version 3 corrects version 1 and the later-known fact corrects the December income (rule 4b), so the contribution is 6.80 % × € 31000.00 = € 2108.00.

**Retroactivity** is a later-known version whose validity starts in the past:

```rezono
  version 3, valid 2026-01-01.., known 2026-03-02  = € 1820.00  @ example-amendment#art-1
```

A question as known 2026-02-01 still uses version 2; from 2026-03-02 on, version 3 applies to the same dates.

**Sealed periods are not rewritten.** A kind may name the slot that seals its elements:

```rezono
kind Month  world closed
  applies at: first_day
  sealed at: closed_on
  first_day: Date
  closed_on: DateTime?
```

Once `closed_on` is known, every derived value of that month keeps its value as known at `closed_on`. A later-known version yields a **correction row** (subject, slot, sealed value, current value, version) that a pack can book in an open period (§14).

**Transition law** is precedence between versions:

```rezono
extend Claim
  derived income_limit: Money<EUR>
    version 1, valid 2025-01-01.., known 2024-09-17  = € 28000.00  @ example-policy#art-2
    version 2, valid 2026-01-01.., known 2025-09-16  = € 30000.00  @ example-policy#art-2
    version 2 replaces 1 unless started_on < 2026-01-01    -- running claims keep the old limit
```

`unless c` is a decision point (§7b): true keeps the replaced version, false or `n/a` the replacing one, and unknown or invalid gives the value that state.

**Proofs.** The witness of a versioned value names the version, the context values and the precedence step; the checker recomputes the selection from these alone.

## 5b. Exceptions

**Ordered precedence** (unchanged): each `unless` block overrides the base definition and every block above it.

**Sibling exceptions.** The lines of one `unless` block are siblings at one precedence level:

```rezono
extend Offer
  derived discount_rate: Ratio = 10 %
    unless
      when preferred then 20 %
      when volume_discount then 15 %    -- sibling of the line above
    unless ineligible then 0 %           -- overrides both
```

`unless c then v` is the one-line form of a block with one line. Per subject, the blocks are read from the last to the first:

1. If every line of the block is false or `n/a`, read the block above; after the first block, the base value applies.
2. If exactly one line is true and the others are false or `n/a`, its value applies.
3. If two or more lines are true, the value is `invalid exception_conflict`, and a violation `exception_conflict` carries the witness of each line. This holds even when the values agree (open point 14): a silent pick hides a modelling error.
4. Otherwise a line is unknown or invalid, so the block cannot decide: the value takes the highest of those states (§7b), with its reason.

The compiler reports R023 when two siblings can be shown to apply together from constants and types (the same condition twice). Otherwise the conflict is found per subject.

**Labelled exceptions from another module (reserved).** A law-like pack may extend a definition it does not own:

```rezono
-- in pack example-amendment, which does not own example-policy.Claim.income_limit
exception transitional_2026 of example-policy.Claim.income_limit
  when started_on < 2026-01-01 then € 28000.00
```

Meaning, fixed now: a sibling line in a new top block of the target; foreign exceptions on one target are siblings of each other. The target must be in the owner's public surface (R032); the label is unique per target. The compiler reports R015 until a later version implements it. Ordering among foreign exceptions is open point 5.

`unless` attaches to value definitions and to version precedence. A relation that needs exceptions is a `derived` Bool; `unless` on a `rule` is open point 6.

## 5c. Decision tables

```rezono
enum Band = none | low | standard

extend Claim
  derived band: Band
    table unique
      | age    | income          | -> band    |
      | ..<18  | -               | none       |
      | 18..   | ..<€ 30000.00   | low        |
      | 18..   | € 30000.00..    | standard   |
```

- The header names input expressions over the subject and, after `->`, the derived value. Each row has one test per input and one output value.
- A cell test is `-` (any value, in any state), a value (equality), a range (`a..b`, `a..<b`, `..<b`, `..b`, `a..`) or alternatives separated by commas. A row applies when every test is true; a test on an `n/a` input does not apply; a test on an unknown or invalid input leaves the row undecided.

| Hit policy | Several rows apply | No row applies |
|---|---|---|
| `unique` | cannot happen: the compiler proves the rows disjoint (R031); at run time it would be `invalid exception_conflict` | `unknown no_row_applies` |
| `first` | the first applying row, in order | `unknown no_row_applies` |
| `priority` | the applying row whose output comes first in the output enum's order | `unknown no_row_applies` |
| `collect` | the set of outputs of all applying rows; the value must be `T*` | `[]`, known and empty |

- An undecided row that could change the outcome makes the value unknown, as in §5b rule 4.
- **Proofs.** Column by column over the input types (enum values, intervals), the compiler proves that `unique` rows are disjoint and that the rows cover the inputs. A gap is W112 with an example input (R024 if `total`). A value's witness names its row.
- See [Decision tables](../../decisions/language-tables.md) for the implemented form, with [the conformance cases](expressions.md#11-conformance-cases).

## 5d. Effect classes and totality

**Effect classes** (Verse) say what a declaration or command may do:

| Class | Declarations | Commands |
|---|---|---|
| `computes` | only facts and definitions of the pinned manifest | checks text against the schema only (check-only: `rezono check`, the MCP check tool, REPL `:check`) |
| `reads` | also an observed relation (source class `observation`) or the manifest’s clock fact; freshness is derived from that published fact | reads rows of a pinned manifest: `ask`, REPL `:row` |
| `transacts` | none | applies a speculative delta and discards it: `suppose` |
| `writes` | none | changes what will be published, through review: `propose` |

Order: `computes` < `reads` < `transacts` < `writes`. A declaration's class is inferred as the highest class of what it reads, transitively; a declared class is an upper bound the compiler checks:

```rezono
extend Run
  reads derived overran: Bool = observed_hours > hours_max   -- observed_hours comes from run_observation
computes rule fits(h: Host, p: Plan) when p.memory >= h.memory_need
```

- Declaring `computes` on a definition that reads is R025. `check` and `require` must compute (R026): observations never block an epoch.
- The class is part of the public surface (§4c).
- The [expression reference](expressions.md#8b-effect-classes) describes the reported effect of each form.

**Totality** (Verse: may fail versus must succeed):

```rezono
extend Host
  total derived cluster_count: Count = clusters.count()      -- a closed, known set: always known
extend Offer
  partial derived euro_price: Money<EUR> = price * rate.value   -- unknown while no rate is published
```

- `total`: the compiler must show that a version applies for every value of the subject's context slots (by type and refinement), that every input is total or always known (`n/a` only through `T?`), and that no exception conflict, table gap or invalid arithmetic can arise; else R024 names what fails.
- `partial` (the default) permits `unknown` or `invalid` with a reason.
- A check over total inputs is never undecided, so W104 cannot fire for it. Totality is part of the public surface (§4c).

## 5e. Testing

**Negative examples.** `expect` may name a violation:

```rezono
example "a plan above its cap is refused"
  given
    p1.hourly_price = € 0.50/h
    p1.max_hourly_price = € 0.30/h
  expect
    violation price_cap on p1
```

`violation <name> [on <id>]` holds when the named check or norm, or a core violation (`exception_conflict`, `versions_overlap`), has a violation row, for that subject if given.

**Contexts.** An example may carry the [context clause of a question](expressions.md#4-grammar): `example "…" at 2026-03-01`, `during stage-a`, `in setup-b`, `as known 2026-02-01`. Versions can be tested that way.

**Coverage** (CI). Every version, `unless` line, table row, calculation line and rule must be used by the proof of some example, and every check must both pass and be violated in some example. CI reports each clause that no example exercises as W109 (a CI report, not a compiler diagnostic).

**Bounded search** (an offload in CI, as in CUTECat, Alloy and Forge). For each check and norm, a solver looks for facts with at most n elements per kind (default 3, open point 12) that violate it; if there are none, CI reports W110. This extends W104, which looks only at unknown inputs. The result is a hint, not a proof for larger instances.

## 5f. Dates, periods and rounding

- `std.units` declares calendar units `month` and `year = 12 month` in their own dimension, apart from time (`s`, `h`, `d`). `1 month = 30 d` is R003.
- `Period<T>` is `Range<T>` over `Date` or `DateTime`, half-open by convention (`2026-01-01..<2027-01-01`). It has `.start`, `.end` and `.length()` (in `d` for dates, `s` for date-times); `d in p` tests membership. Published data represents it with the `Period` type.
- `Date ± n d` is exact; `b - a` of two dates is in `d`. `Date ± n month | year` keeps the day number; if that day does not exist, the pack's **date rounding** decides:

```rezono
rounding date down            -- 2026-01-31 + 1 month = 2026-02-28
rounding money half_even      -- the pack's named rounding for round(x)
```

| Date rounding | `2026-01-31 + 1 month` |
|---|---|
| `down` | `2026-02-28` |
| `up` | `2026-03-01` |
| `exact` | `invalid ambiguous_date` |

- Without a declaration the rounding is `exact`, and the compiler warns once per pack that uses month or year arithmetic (W111). An unknown rounding name is R030.
- `rounding money` declares the pack's one named rounding (§5): `half_even`, `half_up`, `down` or `up`.
- Whole months or years between two dates, and the date of a `DateTime` in a time zone, are open point 8.

## 5g. Sources and interpretations

- `@ example-prices#2026-11-08` names an edition and `@ example-policy#art-2` names an article. The part after `#` is a locator. A source of class `law` can carry an ELI or Juriconnect identifier in its [source record](../../contracts/source.yaml), so the locator resolves to an article URI (§14).
- Versions and exception lines carry their own source, so each value's proof names its article.
- **Competing interpretations** stand side by side as versions `in` an interpretation:

```rezono
kind Reading  world closed            -- elements: strict, lenient

extend Claim
  derived counts_other_income: Bool
    version 1, in strict   = true    @ example-policy#art-3
    version 2, in lenient  = false   @ example-guidance#p4
```

The question chooses the reading (`ask Claim in lenient where …`), or a sweep runs both as variants and compares the rows that differ with their proofs. Without a reading the value is `unknown no_version_applies`. Ids after `in` are read by the subject’s `applies in` slot type when it has one, and otherwise among all kinds (R002 if ambiguous).

## 6. Expressions

| Form | Example | Notes |
|---|---|---|
| path | `x.spec.nodes`, `h.clusters` | free over single values; a multivalued path is a set |
| aggregate | `clusters.sum(count * spec.nodes)`, `.count()`, `.min(…)`, `.max(…)` | inside the parentheses the element's slots are in scope; `it` is the element |
| quantifier | `clusters.any(count > 2)`, `.all(…)`, `.none(…)` | |
| filter | `Host where memory_need > 384 GiB` | a set expression; `it` is the element |
| membership | `x in switch-a.uplinks`, `asn in 65001..65099` | |
| condition | `when c then a else b` | `else` is required in an expression |
| comparison | `= != < <= > >=` | four-state: with a non-known operand the result takes that state (§7b) |
| logic | `and or not =>` | `not` only over a closed world; four-state tables (§7b) |
| state test | `x is known`, `is unknown`, `is n/a`, `is invalid` | always true or false |
| arithmetic | `+ - * /` | exact; units checked; `-` and `/` need spaces when ids are near |
| rounding | `round(x)`, `round(x, half_even)` | the pack's named rounding unless given (§5f) |
| dates | `start + 1 month`, `end - start` | calendar units and the declared date rounding (§5f) |
| time | `price at 2026-11-01`, `price as known 2026-10-26` | one value along the validity and knowledge axes; a postfix that binds to the path before it ([grammar](expressions.md#4-grammar)) |

**Name resolution in aggregates.** Inside `clusters.sum(…)` a name is looked up on the element first, then outside. If it exists in both places, use `it.count` for the element or qualify the outer name with its binder. Outside an aggregate, quantifier or filter, `it` is undefined. See [name resolution](expressions.md#5-name-resolution).

## 7. The type system

1. **Kinds and ids.** Nominal kinds with identity. An id literal is resolved by the expected kind; an id that fits several kinds is an error.
2. **Cardinality.** `T`, `T?`, `T*`, `T+`. A path through a multivalued slot is a set and must be aggregated, quantified or tested for membership before it meets a single value.
3. **Units and dimensions.** Base dimensions (data, time, count, money per currency, calendar) with exact conversion factors. `GiB + Cents` and `Money<USD> + Money<EUR>` are errors. A currency changes only through a rate fact: `ExchangeRate<USD, EUR>`.
4. **Refinements.** `Count >= 1`, `Port in 1..65535`. Literals are checked at compile time, data through violation views.
5. **Value states.** Every value type `T` carries `known | unknown(reason) | n/a | invalid`. The compiler warns when a check can never be met while an input may be unknown. Every operator combines states by fixed tables (§7b).
6. **Worlds.** `not r` requires `r` to be closed. Absence proofs, such as isolation, are therefore type-safe.
7. **Rights.** Each relation has a reader label from `may_read`; a derived relation's label is the join of its premises' labels. A sheet or question for a role that reads above that role is a warning in v0 and an error in v1.
8. **Provenance.** A value whose source is an assumption has type `Assumed<T>` and is shown as such. `requires n sources` is checked against the proof.
9. **Time.** Facts and definitions carry versions with a context and a knowledge date (§5a). The applicable context is per subject. `at` and `as known` select along the validity and knowledge axes.
10. **Literal types.** A literal token is valid only for the expected type's grammar; its fields are typed; a literal type is a refinement of `Text` with a canonical form.
11. **Theories.** `theory Name<T>` is generic over kinds; `view` instantiates it. A view that breaks a theory's check is an error.
12. **Effects.** Every declaration has an effect class, inferred or declared and checked (§5d).
13. **Totality.** A `total` definition has a proven known value; a `partial` one may not (§5d).

## 7b. Truth and value states

A condition takes one of five values: `true`, `false`, `n/a`, `unknown`, `invalid`. The [truth tables](expressions.md#appendix-a-truth-tables-normative) are normative for every implementation. They follow from four rules:

- **Strict operators** (comparison, `in`, arithmetic, paths, `round`, date arithmetic): if every operand is known, compute; else take the highest state of the operands in the order `n/a` < `unknown` < `invalid`. This is the order of the publication state codes 1, 2, 3.
- **`and`** is false if any operand is false; else true if all are true; else the highest state among the rest. **`or`** is the dual. **`not`** keeps a state. **`a => b`** is `not a or b`. As in OCL 2.4, `false and invalid` is false and `true or invalid` is true.
- **Reasons.** A result in a state carries the least reason code (UTF-8 order) among the operands in that state, ties broken by the cause's RowRef. So the tables are commutative in state and in reason.
- **`is`** is always true or false. `when c then a else b` with `c` in a state takes that state. Over a known set, `sum`, `count`, `min` and `max` are strict in the members' states; `min` and `max` of an empty set are `n/a empty`; `any` is an `or` over the members (false for none), `all` an `and` (true for none), `none` is `not any`.

**Decision points.** Inside an expression `n/a` propagates. Where a condition decides, the states mean:

| Condition | `ask` filter | `rule` body | `check`, `require`, `norm` | `unless` line, table row, `replaces … unless` |
|---|---|---|---|---|
| true | in the answer | a row | passes | applies |
| false | left out | no row | violation | does not apply |
| `n/a` | left out, counted as not applicable | no row | passes: does not apply | does not apply |
| unknown, invalid | an undecided row, with reason | an outcome row in that state, with reason | an undecided violation | the value takes that state |

For a host without an owner, `owner = team-platform` and `not owner = team-platform` are both `n/a`, so the host is in neither answer ([E43](cases/E43.yaml)). **Undecided violations and publication.** For `check`, `unknown` publishes an undecided violation with its reason and cause, counted per role. `invalid` blocks. Both states block `require`. `warn` and `norm` never block. A check over `total` inputs is never undecided (§5d).

## 8. Questions, scenarios and changes

```rezono
ask Host where memory_need > 384 GiB                     -- implicit binder: host
ask h: Host where h.memory_need > 384 GiB show h, h.memory_need
ask Claim at 2026-03-01 as known 2026-02-01 where income_limit < € 29000.00

suppose
  + x2.count = 3
  - HostCluster x9
ask Host where memory_need > 384 GiB

propose "Update the example rate"
- plan-a.hourly_price = € 0.1250/h
+ plan-a.hourly_price = € 0.1500/h    @ example-prices#2026-11-15
```

`show` chooses the columns; without it the answer shows the binder and every value the condition reads. `suppose` adds a delta to the session or question only. `propose` is the same delta, sent for review.

The **context clause** after the kind (`at`, `as known`, `during`, `in`) sets the date, knowledge cut, stage and setup for subjects without their own (§5a rule 1). See the [question grammar](expressions.md#4-grammar) and its reserved forms.

**Effect classes** (§5d): `ask` reads, `suppose` transacts, `propose` writes, and a check-only validation of any of them computes.

## 8b. Answers are typed datasets

A query is a migration (CQL). Every `ask` has an **output schema**: the binder’s kind plus each shown expression with its type and states. The answer is a typed dataset whose `$schema` gives the schema id. Unknown or invalid rows are its `Undecided` rows. See [answer schemas](expressions.md#8a-the-answer-is-a-typed-dataset).

- **Answers compose.** An answer at `GET …/ask/q/<hash>` is an immutable dataset with a schema. Reading an answer as a kind is reserved. Asking q2 over q1’s answer would have to equal the composed question ([E53](cases/E53.yaml)).
- **Query execution.** The design runs questions on DuckDB or Feldera over published manifests with a cost budget.

## 11. Grammar (EBNF, core)

`NEWLINE`, `INDENT` and `DEDENT` are layout tokens: Rezono is indentation-sensitive, like Python. A line break ends a statement; a deeper indent opens a block, and returning to the previous indent closes it.

**Lines that go on.** A deeper line continues the preceding statement when either line shows that the statement is unfinished. The preceding line ends in `=`, `=>`, a standalone arithmetic operator (`+`, `-`, `*`, `/` after a space), `(`, `,`, `when`, `then`, `else`, `and`, `or` or `not`, or leaves a parenthesis open. A deeper line starting with `then`, `else`, `and`, `or`, `=>`, `+`, `-`, `*`, `/` or `)` also continues the statement. Ignore comments in both tests. Continued statements emit no `NEWLINE`, `INDENT` or `DEDENT`. Text literals and backticked ids must end on the same line. A comma or word inside either literal does not continue a line.

```ebnf
file        = [ "rezono" int NEWLINE ] "pack" name NEWLINE { use } { decl } ;
use         = "use" qname [ "as" name ] NEWLINE ;
decl        = [ doc ] [ deprecation ] [ "private" ] [ totality ] [ effect ]
              ( unit | enum | literal | param | kind | extend | rule | check | fact | decide
              | assume | theory | view | example | reason | rounding | exception ) ;
deprecation = "deprecated" text "until" date NEWLINE ;
totality    = "total" | "partial" ;                         (* contextual *)
effect      = "computes" | "reads" ;                        (* contextual *)
unit        = "unit" Type "=" ( "integer" | qty | "money" [ "minor" ] Cur [ "per" name ] ) NEWLINE ;
enum        = "enum" Type [ world ] "=" name { "|" name } NEWLINE ;
literal     = "literal" Type ":" "Text" NEWLINE INDENT [ "normalize" name { "," name } NEWLINE ]
              "pattern" text NEWLINE [ "fields" fieldlist NEWLINE ] { "check" expr NEWLINE } DEDENT ;
param       = "param" name ":" type [ "per" Type ] ( [ "=" expr ] NEWLINE | versions ) ;
kind        = "kind" Type [ world ] NEWLINE [ INDENT { applies | sealed | slot | derived } DEDENT ] ;
applies     = "applies" ( "at" | "during" | "in" ) ":" name NEWLINE ;
sealed      = "sealed" "at" ":" name NEWLINE ;                    (* contextual *)
extend      = "extend" Type NEWLINE INDENT { [ totality ] [ effect ] derived } DEDENT ;
slot        = name ":" type [ card ] [ refine ] [ "inverse" name ] [ world ] NEWLINE ;
derived     = "derived" name ":" type [ card ]
              ( "=" expr { unless } NEWLINE | calcdef | versions | NEWLINE INDENT dtable DEDENT ) ;
unless      = NEWLINE "unless" ( expr "then" expr
                          | NEWLINE INDENT { "when" expr "then" expr [ src ] NEWLINE } DEDENT ) ;
calcdef     = [ meta ] NEWLINE INDENT { name ":" "when" expr "then" expr NEWLINE } DEDENT ;
meta        = "version" int { "," context } ;
versions    = NEWLINE INDENT version { version } { precedence } DEDENT ;
version     = meta ( "=" expr [ src ] NEWLINE { unless }
                   | [ src ] NEWLINE INDENT body DEDENT ) ;
body        = "when" expr NEWLINE | "=" expr { unless } NEWLINE | expr NEWLINE
            | { name ":" "when" expr "then" expr NEWLINE } | dtable ;
precedence  = "version" int "replaces" int [ "unless" expr ] NEWLINE ;
context     = "valid" vrange | "known" date | "during" stages | "in" id { "|" id } ;
vrange      = date "..<" date | date ".." ;
stages      = id [ "..<" id | ".." ] ;
rule        = "rule" name "(" binders ")" ( "when" expr NEWLINE | versions | NEWLINE ) ;   (* bare: a theory signature *)
check       = ( "check" | "warn" | "require" | "norm" ) [ name ":" ]
              ( expr [ "requires" int "sources" ] [ "because" source ] NEWLINE | versions ) ;
dtable      = "table" policy NEWLINE INDENT header { trow } DEDENT ;          (* reserved *)
policy      = "unique" | "first" | "priority" | "collect" ;
header      = "|" expr { "|" expr } "|" "->" name "|" NEWLINE ;
trow        = "|" cell { "|" cell } "|" value "|" NEWLINE ;
cell        = "-" | test { "," test } ;
test        = value [ ( ".." | "..<" ) [ value ] ] | ( ".." | "..<" ) value ;
fact        = "fact" ( Type table
                     | name id { "," context } NEWLINE INDENT { name "=" value [ src ] NEWLINE } DEDENT ) ;
decide      = "decide" text "by" name "on" date { "," context } [ src ] NEWLINE INDENT { assign NEWLINE } DEDENT ;
assume      = "assume" assign [ "until" "confirmed" ] NEWLINE ;
theory      = "theory" Type "<" Type ">" NEWLINE INDENT { rule | check } DEDENT ;
view        = "view" Type "as" qname "<" Type ">" NEWLINE INDENT { name "(" binders ")" "=" expr NEWLINE } DEDENT ;
example     = "example" text { qcontext } NEWLINE INDENT "given" NEWLINE INDENT { assign NEWLINE } DEDENT
              "expect" NEWLINE INDENT { ( expr | "violation" name [ "on" id ] ) NEWLINE } DEDENT DEDENT ;
reason      = "reason" name "=" text NEWLINE ;                    (* contextual *)
rounding    = "rounding" ( "date" | "money" ) name NEWLINE ;      (* contextual *)
exception   = "exception" name "of" qname NEWLINE INDENT { "when" expr "then" expr [ src ] NEWLINE } DEDENT ;  (* reserved *)
ask         = "ask" [ name ":" ] Type { qcontext } "where" expr [ "show" expr { "," expr } ] ;
qcontext    = "at" atom | "as" "known" atom | "during" atom | "in" atom ;
type        = Type | Type "<" type { "," type } ">" ;
card        = "?" | "*" | "+" ;
world       = "world" ( "open" | "closed" ) ;
src         = "@" sourceref ;                                (* sourceref may end in "#" locator, §5g *)
literal_tok = token | Type text ;   (* a token is read by the expected type's literal grammar *)
state       = "known" | "unknown" | "n/a" | "invalid" ;
expr        = cond | expr binop expr | "not" expr | expr "is" state | path | literal | call ;
path        = atom { "." ( name | agg ) } [ timesel ] ;
timesel     = "at" atom [ "as" "known" atom ] | "as" "known" atom ;
agg         = ( "sum" | "count" | "min" | "max" | "any" | "all" | "none" ) "(" [ expr ] ")" ;
cond        = "when" expr "then" expr "else" expr ;
```

See the detailed [expression grammar](expressions.md#4-grammar), including precedence.

## 13. Not in v0

- Rights violations as errors (v1; warnings in v0).
- Defeasible logic beyond ordered `unless` blocks, sibling exceptions and labelled exceptions (§5b).
- Arithmetic inside recursion.
- Paths that select a slot on a different node.
- Unit conversions beyond exact factors and rate facts (no temperature offsets, no non-linear units).
- **Reserved** (R015 until supported): foreign `exception … of`, `order by`, `limit`, `group by`, multiple binders, reading an answer as a kind, and evaluation of question contexts and time selection. See [expressions and questions](expressions.md#1-what-is-frozen-and-what-is-reserved).
- Bounded search as a proof: W110 is a hint for small instances (§5e).
- Legal case processing, such as objections and appeals. The language models and verifies rules and can show their impact.
- A query engine of its own (§8b).

## 14. Design boundaries and open points

1. **Support window** for old language versions (§4b).
2. **Question date versus subject date.** The subject’s `applies at` wins. Parameter and relation reads inside a calculation inherit the calculation’s date unless a related object names its own. The question’s date, then the manifest’s, is the fallback. `as known` supplies the separate knowledge cut (§5a rule 6).
3. **Undecided violations.** `check` blocks on `false` and `invalid`. It publishes `unknown` as an undecided violation row. `require` blocks on all three (§5, §7b).
4. **Correction rows:** name and form of the relation, and how a pack books it (§5a).
5. **Several foreign exceptions on one target:** their order, e.g. `over <label>` (§5b).
6. **`unless` on relational rules** (§5b).
7. **`partial` and `decide`.** `partial` describes a definition that may fail to produce a known value. `decide` records a decision for publication through a proposal (§5d).
8. **Calendar differences:** whole months or years between dates; a `DateTime`'s date per time zone (§5f).
9. **Locator forms** per source scheme (§5g).
10. **Manifest default stage and setup** (§5a).
11. **Subject of a rule:** draft the first binder; how to name another (§5a).
12. **Bounds and oracles:** search bound and solver; a DMN test suite for tables (§5c, §5e).
13. **Enum world.** Draft: closed unless declared open (§4c).
14. **Agreeing siblings.** Draft: a conflict even when values agree (Catala). Alternative: allow equal values (§5b).
15. **`warn` and publication.** `warn` and `norm` never block publication (§5, §7b).
16. **Later-known supersedes.** Draft: a later `known` date resolves an overlap (retroactivity, §5a rule 4). Alternative: every overlap needs an explicit `replaces`.
17. **Plain syntax errors.** The [implementation](../../rezono/README.md#what-the-parse-reports) uses R000 at the point where the input stops matching the grammar.
