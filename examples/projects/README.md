# Example: projects and tasks

A familiar domain, chosen so every Rezono construct has a place in the coming milestones.

| Construct | Where | Milestone |
|---|---|---|
| arrow, totality, functionality | each task belongs to exactly one project (`task.project`) | M1 |
| path equation | the project of a task's milestone is the task's project (`task.same_project`) | M1 |
| unique key | a name belongs to at most one project; a (task, prerequisite) pair occurs once | M1 |
| value range | task status is an enum; estimate between 1 and 200 hours; non-negative amounts | M1 |
| recursion | a task depends, directly or through other tasks, on a prerequisite (`dependency`) | M2 |
| negation | a task is blocked if a prerequisite is not `done` | M2 |
| aggregation | the number of open tasks per project | M2 |
| invariant | a project's budget lines add up to its budget, in cents | M3 |

- `schema/`: the LinkML schema, read as an olog;
- `labels/nl.yaml` and `messages/nl.mf2`: words and sentences;
- `channels.yaml`: visual language;
- `facts/valid.yaml`: a valid state;
- `facts/errors.yaml`: the same state with deliberate errors, each with its expected view;
- `expected/`: recorded compiler output (`compiled/`), rendered sentences and expected violations per fact set.

Expected violations are handwritten, not generated by the compiler.

- `proof/engine_proof.py`: the engine proof: M2 rules, handwritten as SQL, on Feldera and DuckDB ([M1 engine proof](../../docs/archive/m1-engine-proof.md)).
